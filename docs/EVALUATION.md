# 평가 대비: 예상 질문과 근거 코드

답변을 외우지 말고 **현상 → 원리 → 코드/검증 명령** 순서로 설명한다. 명령이 실제로 실행됐는지 확인하지 않은 항목은 완료라고 답하지 않는다.

| 질문 | 답변의 핵심 논리 | 코드/검증 위치 |
|---|---|---|
| 1. SSH 포트를 왜 20022로 변경하는가? | 기본 22 포트에 집중되는 자동 탐색을 줄이지만 근본 인증 보안을 대체하지 않는다. 실제 수신 상태도 확인해야 한다. | `secure-network.sh`: `Port 20022`, `sshd -T`, `ss -ltn` |
| 2. Root 원격 접속을 왜 차단하는가? | 특권 계정 직접 로그인을 막아 권한 남용·침해 범위를 줄인다. 일반 계정+필요 시 sudo가 바람직하다. | `PermitRootLogin no`; `sshd -T -C user=root,...` |
| 3. 왜 UFW에 두 포트만 허용하는가? | 기본 거부가 공격 노출 면적을 줄인다. SSH 20022와 앱 15034만 필수이다. | `ufw default deny incoming`, `ufw allow ...`, `ufw status` |
| 4. SSH 설정과 방화벽의 역할은 어떻게 다른가? | SSH는 서비스의 포트·인증 정책, 방화벽은 호스트로 유입되는 패킷 허용/차단이다. 둘 다 맞아야 연결된다. | `secure-network.sh`; `sshd -T`와 `ufw status` 비교 |
| 5. 두 그룹을 분리한 이유는? | QA에는 업로드 권한이 필요하지만 키·로그 권한은 불필요하다. 최소 권한과 역할 분리를 구현한다. | `provision.sh`의 `usermod`, `id agent-*` |
| 6. `chmod 750`이 무엇인가? | 소유자 rwx(7), 그룹 r-x(5), 기타 없음(0). admin이 dev 소유 스크립트를 core 그룹 자격으로 실행한다. | `install ... -m 750` / `stat` |
| 7. ACL과 setgid가 왜 필요한가? | 그룹별 진입권과 새 파일의 권한 상속을 다룬다. `--x`는 디렉토리 목록이 아닌 진입만 허용한다. | `setfacl`, `getfacl`, `chmod 2770` |
| 8. `AGENT_HOME`을 사용하는 이유는? | 환경별 경로를 하나의 설정으로 관리하고 앱·업로드·키 위치를 일관되게 전달하기 위해서다. | `agent-app.env`, `run-app.sh`의 `source` |
| 9. `cron`은 환경 변수를 자동으로 받는가? | 로그인 프로필을 자동으로 읽지 않는다. 그래서 앱 실행 시 파일을 명시적으로 읽고 모니터에는 고정 기본값을 둔다. | `run-app.sh`/`monitor.sh` 환경 설정 |
| 10. 프로세스와 포트를 모두 확인해야 하는 이유는? | 앱이 존재해도 포트가 열리지 않을 수 있고, 반대로 다른 프로세스가 포트를 점유할 수 있다. PID까지 교차 검증한다. | `monitor.sh`: `pgrep`, `ss`, PID 비교 |
| 11. `exit 1`과 `[WARNING]` 기준은? | 앱 프로세스/포트 오류는 서비스 건강성 실패, 방화벽·리소스는 운영 경고다. 경고 중에도 수치는 저장한다. | `fail()`, UFW `if`, `warn_if_high()` |
| 12. CPU 측정에 `vmstat 1 2`가 쓰이는 이유는? | 첫 행은 부팅 이후 평균, 두 번째가 샘플 구간 통계다. `100 - idle` 계산. | `cpu=$(vmstat ...)` |
| 13. 메모리의 `available`은 무엇인가? | 해제 가능한 캐시 등을 고려한 가용 메모리 추정치로, 무작정 사용량을 과대평가하지 않기 위해 활용한다. | `free -b` 수집 수식 |
| 14. 20/10/80 임계값을 정확히 찍으면 경고인가? | 아니다. 요구사항은 초과(`>`)다. 소수점 비교는 `awk`가 수행한다. | `warn_if_high`, 모의 테스트 1·6 |
| 15. 로그가 10MiB를 넘으면 어떻게 되는가? | 활성 파일+9개 회전 파일 이내로 유지한다. `.9` 제거, 역순 번호 이동, 새 활성 파일 기록. | 회전 루프, 모의 테스트 7 |
| 16. `flock`은 왜 필요한가? | cron과 수동 실행이 겹쳤을 때 두 프로세스가 동시에 로그 파일을 돌려 쓰는 경쟁 상태를 예방한다. | `exec 9>...`, `flock -n 9` |
| 17. cron이 정상 등록됐다는 증거는? | crontab의 `* * * * *` 한 줄과 **1~2분 이후** 타임스탬프가 늘어난 `monitor.log` 두 증거가 모두 필요하다. | `crontab -u agent-admin -l`, `tail` |
| 18. 어떤 항목이 아직 실제 검증 대상인가? | 제공 앱 원본과 실습 VM이 없어 SSH/UFW/ACL/Boot/cron의 실제 상태는 미확인이다. Bash 테스트 통과와 혼동하지 않는다. | `docs/RESULTS.md` |

**코드를 읽을 순서:** `provision.sh`(시스템 상태 변경) → `secure-network.sh`(원격 접속 정책) → `run-app.sh`(앱 프로세스) → `monitor.sh`(관제 흐름) → `test_monitor.sh`(실패/경계 케이스). 검증 자료 작성 시에는 `verify.sh`로 실측 출력을 확보한다.
